# 아이템과 장착 무기

코스튬은 회원 단위로 보유하고, 아이템은 캐릭터 단위로 보유한다. 현재 장착을 지원하는 슬롯은 무기(`WEAPON`)다. 인벤토리·무기 선택 UI, 관리자 업로드·편집, 거래·강화·전투 능력치는 아직 구현하지 않았다.

## 테이블

`V7__gm_item_weapon.sql`에서 다음 테이블을 만든다.

| 테이블 | 역할 |
|---|---|
| `gm_item` | 아이템 정의: 고유 코드, 이름, 설명, 종류, 장착 슬롯, 외형 코드, 관리 상태, 등록·수정 일자 |
| `gm_character_item` | 실제 보유 아이템: UUID, 캐릭터, 아이템 정의, 수량, 획득·수정 일자 |
| `gm_character_equipment` | 슬롯별 장착: 캐릭터, 슬롯 코드, 보유 아이템 UUID, 등록·수정 일자 |

아이템 종류는 `WEAPON`, `ARMOR`, `CONSUMABLE`, `MATERIAL`, 관리 상태는 `DRAFT`, `ACT`, `INACTIVE`다. 장착 무기는 보유 행마다 수량 1로 저장한다. 같은 종류의 무기라도 보유 UUID가 달라 향후 개별 강화 수치를 추가할 수 있다. 비장착 아이템의 수량도 저장할 수 있으나 겹치기 한도·사용 효과 등은 아직 정의하지 않았다.

슬롯별 고유 제약으로 같은 캐릭터의 한 슬롯에는 하나만 장착할 수 있다. 보유 UUID 고유 제약으로 한 아이템을 중복 장착할 수 없다. 캐릭터·보유 UUID 복합 외래키로 다른 캐릭터의 보유 아이템 참조를 막는다. 장착 API는 추가로 로그인 회원의 캐릭터인지, 해당 캐릭터의 수량 1인 사용 중 무기인지 확인한다.

캐릭터 삭제 시 닉네임과 소유자를 확인하고 캐릭터 행을 잠근 뒤 장착 정보 → 보유 아이템 → 캐릭터 순서로 명시적으로 삭제한다. 회원 공유 코스튬과 아이템 정의는 유지한다. 장착·해제도 같은 캐릭터 행을 잠가 동시 요청을 직렬화한다. FK 참조 동작 옵션은 사용하지 않는다.

## 기본 몽둥이

- 아이템 코드와 외형 코드: `wooden-club`
- 최초 아이템 UUID: `20000000-0000-4000-8000-000000000001`
- 이름: `몽둥이`, 종류·슬롯: `WEAPON`, 상태: `ACT`
- 이미지: `local-assets/weapons/wooden-club.png`
- HTTP 경로: `/asset-files/weapons/wooden-club.png`
- 원본은 새로 제공된 64×64 투명 PNG로 교체했다. 로컬 파일과 번들 대체 이미지 모두 `wooden-club.png` 파일명을 유지하며, 게임에서는 64×64로 표시한다. 선택창은 데스크톱 64×64, 모바일 48×48로 표시한다.

마이그레이션은 기존 캐릭터마다 몽둥이 1개를 지급·장착한다. 새 캐릭터도 생성 트랜잭션에서 코스튬 지급·캐릭터 저장·몽둥이 지급·장착을 함께 처리한다. 기본 무기 정의가 없거나 비활성 상태여서 지급하지 못하면 생성 전체를 롤백한다. 기본 정의는 외형 코드가 아닌 고유 `item_code`로 조회하므로 나중에 외형 이미지를 바꿀 수 있다.

기본 정의 INSERT문은 [default_weapon.sql](../sql/default_weapon.sql)에 있다. Flyway V7이 자동 등록하므로 별도로 실행할 필요는 없다. 관리자 목록을 만들 때는 같은 `gm_item` 행을 조회하면 된다. 외형 코드는 설정된 에셋 폴더의 `weapons/{appearanceCode}.png`로 조합한다. 파일을 추가·교체한 뒤 새로고침하면 표시된다.

## API

- `GET /api/characters/{characterId}/items`: 본인 캐릭터의 보유 목록. `characterItemId`, `itemId`, `itemCode`, `name`, `itemType`, `quantity`, `appearanceCode`, `equipped`를 반환한다. 본인 캐릭터가 아니면 빈 목록이다.
- `PUT /api/characters/{characterId}/weapon`: `{ "characterItemId": "UUID" }`로 장착한다. 반드시 아이템 정의 UUID가 아닌 보유 UUID를 보낸다. `null`이면 장착만 해제하고 보유 행은 유지한다. 본인 캐릭터가 아니면 404, 장착 불가능한 아이템은 400이다.
- `GET /api/characters`와 생성 응답에는 `weapon`이 추가된다. 장착 시 `{ characterItemId, itemId, itemCode, name, appearanceCode }`, 미장착 시 `null`이다.

모든 API는 로그인 세션을 확인하고 캐시하지 않는다. 변경 요청은 CSRF 헤더가 필요하다. 변경 후 목록을 다시 조회하면 선택창에도 해당 무기 또는 미장착 상태가 반영된다. 임의 아이템 지급 API는 노출하지 않는다.

선택창과 게임 화면의 무기는 캐릭터와 별도 이미지이며 수직으로만 떠다닌다. 장착하지 않았거나 잘못된 외형 코드이면 표시하지 않는다. 기본 몽둥이 이미지 누락은 번들 이미지로 대체하고 다른 무기의 이미지 누락은 숨긴다. 선택창의 걷기 모션과 무기 부유 모션은 동작 줄이기 설정에서 정지한다. 게임 화면에서는 캐릭터의 조작에 따른 걷기·점프는 유지하고 무기 부유를 정지한다. 게임에서 Z로 장착 무기를 휘두를 수 있다. 장비·인벤토리 UI 및 몬스터 명중·피해 판정은 아직 구현하지 않았다.
