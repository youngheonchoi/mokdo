# 숲 몬스터 전투와 성장 (V17)

관리자에 등록한 고유 코드 `tmffkdla`의 **사용 중(ACT)** 몬스터 한 마리를 벨트스크롤 숲에 배치한다. 캐릭터마다 독립된 전투이며 다른 캐릭터와 몬스터 체력을 공유하지 않는다. `mokdo_admin` 수정 없이 기존 몬스터 능력치·보상·드롭과 레벨 설정을 사용한다.

## 플레이 흐름

- 캐릭터 시작점은 (400, 560), 몬스터 생성점은 (800, 560)이다. 최초 입장에는 이 위치를 사용하고 이후 입장에는 같은 서버 프로세스의 메모리에 있는 전투 위치·몬스터 체력·리스폰 상태를 복원한다. 서버 재시작 또는 30분 이상 중단 후 재입장하면 전투는 시작점에서 초기화한다. 캐릭터 체력·아이템·경험치·재화·레벨은 DB에 유지한다.
- 몬스터는 260px 이내의 캐릭터를 추적한다. 범위를 벗어나면 공격을 멈추고 생성 위치 (800, 560)로 걸어서 돌아간다. 복귀 중에는 다시 쫓지 않고, 도착한 뒤 범위 안의 캐릭터를 다시 추적한다. 복귀만으로 체력을 회복하거나 보상을 지급하지 않는다. 이동 속도는 좌우 기준 85px/초이며 바닥 앞뒤 이동 비율은 0.6이다. 근접 시 1.2초 간격으로 공격한다.
- Z를 누르거나 계속 누르면 400ms 간격으로 공격하며 맨손 공격도 가능하다. 휘두르기 시작 약 90ms 뒤의 접촉 위치로 한 번 판정하고, 화면에서 몬스터 체력 감소·피격 색·피해 숫자를 즉시 표시한다. 서버는 공격 번호·몬스터 생성 세대·최근 위치·사거리·공격 속도 예산을 확인하고 실제 피해와 처치를 확정한다. 응답을 기다리는 동안 발생한 여러 공격은 입력 묶음으로 전달해 누락하지 않으며 같은 공격 번호를 다시 처리하지 않는다. 바라보는 방향 앞으로 110px, 뒤쪽 허용 18px, 바닥 Y 차이 38px 이내에 있어야 명중한다. 피해는 `max(1, 공격력 - 방어력)`이며 장비 합산 후 수치를 사용한다.
- 캐릭터·몬스터 피격 시 피해 숫자와 색 변화, 체력 감소를 표시한다. 몬스터는 처치 시 사라졌다가 5초 후 원래 생성점에 최대 체력으로 리스폰한다.
- 캐릭터 체력이 0이면 이동·공격을 막고 사망 프레임과 부활 카운트다운을 표시한다. 5초 뒤 시작점에서 최대 체력으로 부활하며 경험치·재화·아이템 손실은 없다. 살아 있는 몬스터도 이때 생성점에서 체력을 회복한다. 이미 처치한 몬스터의 리스폰 타이머는 유지한다.
- Space 점프 중 공중 구간에는 몬스터 근접 공격을 피한다. 이륙·착지 구간에는 피해를 받을 수 있다. 바닥 좌표와 점프 높이는 분리한다.
- 인벤토리·장비창을 열거나 탭을 숨기면 전투 진행을 일시 정지한다. 재접속으로 캐릭터 체력이나 처치한 몬스터의 상태를 초기화하지 않는다.

## 보상과 성장

처치에 따른 드롭 추첨·아이템 지급·경험치·재화·레벨업·캐릭터 체력 저장은 하나의 DB 트랜잭션에서 처리한다. 전투 상태의 복사본을 계산한 뒤 DB 커밋이 성공해야 서버 메모리에 반영한다. 실패하면 지급과 몬스터 체력 변경을 모두 취소한다. 화면에서 경험치·재화를 바닥 아이템으로 만들지 않으며, **몬스터의 처치 위치 머리 위에 `+숫자 경험치`, `+숫자 재화`**를 띄운다. 아이템도 즉시 인벤토리에 지급하고 `+아이템 이름 ×수량`으로 알린다.

- 경험치·재화는 관리자 몬스터 정의의 `reward_exp`, `reward_currency`를 사용한다. 재화는 캐릭터 단위로 저장한다.
- 드롭 항목별 확률을 독립 추첨하고 설정된 최소~최대 수량을 지급한다. 사용 중인 아이템 정의만 지급한다. 확률 0%는 지급하지 않고 100%는 반드시 지급한다.
- 무기·모자는 개별 보유 UUID와 수량 1로 지급한다. 다른 종류는 같은 아이템의 기존 보유 수량에 합산하며 INTEGER 수량 범위를 넘으면 새 보유 행을 만든다. 한 번에 지급할 무기·모자의 합계가 1000개를 넘으면 잘못된 보상 설정으로 처리하고 처치 전체를 롤백한다.
- `gm_character_level.required_exp`만큼 경험치가 쌓이면 차감 후 다음 **등록된 연속 레벨**로 상승한다. 보상이 크면 여러 레벨을 한 번에 올리고 나머지 경험치를 보관한다. 레벨업 시 변경된 기본·장비 능력치를 다시 조회하고 최대 체력으로 회복한다.
- 최고 설정 레벨(`required_exp=NULL`)에서는 레벨을 새로 만들지 않고 경험치를 누적한다. 따라서 레벨업을 시험하려면 관리자에서 다음 레벨과 이전 레벨의 필요 경험치를 먼저 등록해야 한다.
- BIGINT 범위를 넘는 누적 경험치·재화는 최댓값에서 멈춘다. 재화 팝업은 실제 증가분을 표시한다.

## 저장과 API

DB에는 기존 `gm_character`의 `current_hp`(최초 전투 전 NULL), `currency`(기본값 0)와 기존 아이템·경험치·레벨 정보만 저장한다. 위치·몬스터 체력·리스폰·공격 간격·화면 표시 알림은 DB에 저장하지 않는다.

V17은 `gm_character_battle_event`, `gm_character_battle`을 삭제한다. 이미 적용된 DB의 Flyway 체크섬 오류를 피하기 위해 과거 V16 파일은 수정하지 않고 유지한다. 게임 백엔드를 재시작하면 V17이 적용되며, 캐릭터 성장·보유 아이템·관리자 설정은 유지한다.

캐릭터 응답은 `currentHp`, `currency`를 포함한다. 장비 해제·관리자 수정으로 최대 체력이 내려가면 현재 체력 표시와 다음 전투 저장도 그 값 이하로 제한한다. 현재 메모리 전투 구현은 게임 서버 한 인스턴스를 기준으로 한다.

| API | 역할 |
|---|---|
| `POST /api/characters/{id}/battle` | 본인 캐릭터 전투 입장·재접속. 새 화면 세션 ID 발급, 기존 전투 상태 유지 |
| `POST /api/characters/{id}/battle/tick` | 세션·입력 순번·이동 방향·공격·점프·일시 정지 전달. 전투 상태·캐릭터 능력치와 해당 입력의 일회성 표시 정보(`effects`) 응답 |
| `GET /api/monsters/{id}/image` | 사용 중 몬스터의 저장된 PNG를 인증 후 조회 |

모든 전투 변경 요청은 로그인·CSRF·캐릭터 소유를 확인한다. 캐릭터 행 잠금으로 장비 변경·캐릭터 삭제·전투 요청을 직렬화한다. 이동량·공격 간격·사거리·몬스터 AI·피해·보상은 서버가 계산하며 클라이언트가 피해량이나 보상 수량을 제출하지 않는다. 전투 진행 시간은 요청당 최대 1초로 제한한다. 이동 입력은 클라이언트가 프레임별 실제 이동량을 누적해 전달하고 서버가 경과 시간과 이동 속도 예산으로 검증한다. 0.25초의 작은 여유로 통신 지연 변동을 흡수하며, 요청 횟수를 늘려도 속도 제한을 넘지 못한다. 화면은 응답을 기다리는 동안의 이동을 유지하고 차이만 약 160ms에 걸쳐 부드럽게 보정한다. 몬스터는 화면에서 매 프레임 같은 추적 속도로 계속 이동한다. 서버 응답은 통신 중의 진행량을 고려해 위치 오차만 부드럽게 보정하며, 응답 사이에 멈춰서 기다리지 않는다.

한 캐릭터는 가장 최근 입장한 화면 세션만 진행할 수 있다. 같은 캐릭터의 메모리 전투 계산과 DB 커밋을 순서대로 처리하고 같은 입력 순번을 재처리하지 않으므로 처치 보상을 중복 지급하지 않는다. 캐릭터 삭제는 기존 장착 → 보유 아이템 → 캐릭터 순서로 처리하며 삭제된 캐릭터의 전투 상태는 접근 시 또는 유휴 정리 시 메모리에서 제거한다.

`effects`는 피해·실제 지급량·표시 위치를 담은 해당 전투 응답의 일회성 정보다. 화면에서 숫자·피격·보상 연출에 사용한 후 버리며 저장·조회·이력·순번·재전달 로직은 없다. 보상 표시를 위해 별도의 서버 요청을 하지 않는다. 응답이 유실되면 그 응답의 팝업은 생략될 수 있지만 DB에 저장된 실제 아이템·경험치·재화·성장은 다음 상태 응답과 인벤토리에서 확인할 수 있다.

연결 실패 시 이동·공격을 중지하고 2초 간격으로 같은 세션에 재연결한다. 세션이 다른 화면으로 대체되면 안내에 따라 캐릭터 선택으로 돌아가 재입장한다. 몬스터가 없거나 사용 중이 아니면 관리자 설정 안내를 표시한다. PNG가 없거나 로드에 실패하면 이름·체력과 `이미지 없음` 대체 표시로 전투를 시험할 수 있다.

## 검증

`BATTLE_TEST_POSTGRES_URL=jdbc:postgresql://127.0.0.1:포트/battle_test ./gradlew test`로 전용 폐기용 DB에서 테스트한다. DB 계정은 `battle_test` / `battle_test_password`이며 테스트가 관련 데이터를 초기화하므로 공용 개발 DB에 연결하지 않는다. 테스트는 로컬 호스트·DB 이름을 확인한 뒤 V17까지 마이그레이션한다.

실제 PostgreSQL에서 동시 중복 처치, 재접속·서비스 재생성, 드롭 0/100%, 장비 개별 지급·재료 합산, 여러 단계 레벨업, 사망·부활, 점프 회피, 잘못된 드롭 설정의 전체 롤백, 서버 재시작 시 전투 초기화·보상 유지, 캐릭터 삭제 및 두 전투 테이블 제거를 검증한다. 표시 정보는 저장하거나 재전달하지 않는다. 공격 입력은 확인 번호를 받을 때까지 메모리에서 유지하고 재전달할 수 있지만, 이미 표시한 피해 숫자는 서버 확인 시 다시 표시하지 않는다. 이전 몬스터의 공격 입력은 리스폰한 새 몬스터에 적용하지 않는다.

이미지 공개 주소는 스토리지 엔드포인트뿐 아니라 버킷 경로까지 포함해야 한다. 로컬 기본값은 `…/mokdo-dev-assets`이며 `S3_PUBLIC_BASE_URL`을 지정할 때도 버킷 경로를 포함한다. 새 DB·스토리지로 이전한 뒤에는 새 `gm_monster.image_key`와 이 주소가 같은 저장소를 가리키는지 확인한다.

타격 표시를 먼저 계산한 값과 서버 결과가 다르면 서버 체력으로 보정한다. 아이템·경험치·재화·레벨업 보상은 항상 서버의 처치 확정 응답을 받은 뒤에만 표시·반영한다.
