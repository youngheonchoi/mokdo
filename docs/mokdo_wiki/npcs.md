# NPC 관리

Flyway V15는 `gm_npc`, `gm_npc_shop_item`을 만든다. 마이그레이션은 게임 백엔드에서 실행한다.

## NPC와 상점

- NPC는 UUID, 고유 코드, 이름(100자), 설명·대화 문구(관리자 입력 각각 2000자), 외형 이미지 키, 상태, 등록·수정 일시를 저장한다.
- 코드는 소문자·숫자로 시작하는 소문자·숫자·밑줄·하이픈 1~64자이며 등록 후 변경하지 않는다.
- 상태는 DRAFT(작성 중), ACT(사용 중), INACTIVE(사용 중지)다. NPC 물리 삭제 화면은 제공하지 않는다.
- 판매 항목은 NPC와 기존 `gm_item`을 FK로 연결한다. `(npc_id, item_id)` 고유 제약으로 NPC별 중복 판매 항목을 막지만, 서로 다른 NPC는 같은 아이템을 다른 가격으로 판매할 수 있다.
- `price`는 아이템 1개당 기본 재화 가격이며 0 이상의 BIGINT다. 0은 무료다. 재화는 한 종류, 재고는 무제한으로 시작한다.
- `sort_order`는 0 이상의 INTEGER이며 작은 값부터 표시한다. 같으면 아이템 이름·코드 순으로 정렬한다.
- `sale_status`는 ACT(판매 중), INACTIVE(판매 중지)이며 아이템 자체의 관리 상태와 별개다. 향후 게임 상점은 NPC·판매 항목·아이템 모두 사용 중인지 확인해야 한다.
- 판매 항목 저장·삭제 시 NPC 행을 잠그고, 해당 NPC의 판매 행만 수정·삭제한다. FK 참조 동작 옵션은 사용하지 않는다.

## 관리자 화면

- 활성 ADMIN·SUPER_ADMIN이 `/npcs`에서 이름·코드 검색, 상태 필터, 20개 단위 목록을 조회한다.
- `/npcs/new`에서 NPC를 등록하고 `/npcs/{id}`에서 이름·설명·대화 문구·상태와 외형을 수정한다.
- 상세 판매 목록에서 기존 아이템 이름·코드 검색 후 연결한다. 각 행에서 가격·표시 순서·판매 상태를 수정하고 삭제할 수 있다.
- 모든 쓰기 요청은 로그인과 CSRF 토큰이 필요하며 입력 오류는 같은 화면에 표시한다.
- 외형은 선택적 PNG 한 장, 가로·세로 각각 1~2048 픽셀, 최대 5MB다. 서버에서 PNG 시그니처·크기·디코딩을 검증하고 원본 바이트를 유지한다.
- 기존 Neon S3 환경설정으로 `npcs/{npcId}/{imageId}.png`에 업로드한다. DB 롤백 시 새 파일을 정리하며 교체 전 파일은 유지한다. 관리자 이미지 조회는 인증이 필요하다.

현재 작업은 NPC·상점 정의와 관리자 관리까지다. 맵 배치·게임 내 대화와 상점 UI·구매 API·재화 차감 및 아이템 지급·외형 애니메이션은 별도 구현 대상이다. 구매 구현 시 서버에서 가격과 판매 가능 상태를 확인하고 재화 차감·아이템 지급을 한 트랜잭션으로 처리해야 한다.
