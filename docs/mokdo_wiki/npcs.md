# NPC 관리

Flyway V15는 `gm_npc`, `gm_npc_shop_item`을 만든다. 마이그레이션은 게임 백엔드에서 실행한다.

## NPC와 상점

- NPC는 UUID, 고유 코드, 이름(100자), 설명·대화 문구(관리자 입력 각각 2000자), 외형 이미지 키, 상태, 등록·수정 일시를 저장한다.
- 코드는 소문자·숫자로 시작하는 소문자·숫자·밑줄·하이픈 1~64자이며 등록 후 변경하지 않는다.
- 상태는 DRAFT(작성 중), ACT(사용 중), INACTIVE(사용 중지)다. NPC 물리 삭제 화면은 제공하지 않는다.
- 판매 항목은 NPC와 기존 `gm_item`을 FK로 연결한다. `(npc_id, item_id)` 고유 제약으로 NPC별 중복 판매 항목을 막지만, 서로 다른 NPC는 같은 아이템을 다른 가격으로 판매할 수 있다.
- `price`는 아이템 1개당 기본 재화 가격이며 0 이상의 BIGINT다. 0은 무료다. 재화는 한 종류, 재고는 무제한으로 시작한다.
- `sort_order`는 0 이상의 INTEGER이며 작은 값부터 표시한다. 같으면 아이템 이름·코드 순으로 정렬한다.
- `sale_status`는 ACT(판매 중), INACTIVE(판매 중지)이며 아이템 자체의 관리 상태와 별개다. 향후 게임 상점은 NPC·판매 항목·아이템 모두 사용 중인지 확인해야 한다.
- 판매 항목 저장·삭제 시 NPC 행을 잠그고, 해당 NPC의 판매 행만 수정·삭제한다. FK 참조 동작 옵션은 사용하지 않는다.

## 관리자 화면

- 활성 ADMIN·SUPER_ADMIN이 `/npcs`에서 이름·코드 검색, 상태 필터, 20개 단위 목록을 조회한다.
- `/npcs/new`에서 NPC를 등록하고 `/npcs/{id}`에서 이름·설명·대화 문구·상태와 외형을 수정한다.
- 상세 판매 목록에서 기존 아이템 이름·코드 검색 후 연결한다. 각 행에서 가격·표시 순서·판매 상태를 수정하고 삭제할 수 있다.
- 모든 쓰기 요청은 로그인과 CSRF 토큰이 필요하며 입력 오류는 같은 화면에 표시한다.
- 외형은 선택적 PNG 한 장, 가로·세로 각각 1~2048 픽셀, 최대 5MB다. 서버에서 PNG 시그니처·크기·디코딩을 검증하고 원본 바이트를 유지한다.
- 기존 Neon S3 환경설정으로 `npcs/{npcId}/{imageId}.png`에 업로드한다. DB 롤백 시 새 파일을 정리하며 교체 전 파일은 유지한다. 관리자 이미지 조회는 인증이 필요하다.

## 숲 배치와 게임 상점

게임은 사용 중(`ACT`)인 NPC를 등록일·UUID 순서로 읽어 숲길 초입에 배치한다. 현재 두 NPC의 바닥 좌표는 (260, 510), (540, 510)이며, 별도 위치 컬럼을 추가하지 않고 프런트에서 배치를 결정한다. 이름과 `상점` 표시를 누르면 대화 문구와 판매 상품을 볼 수 있다. 관리자가 업로드한 정적 PNG를 게임의 인증된 이미지 API로 표시하며 이미지가 없으면 상인 대체 표시를 사용한다. 애니메이션은 아직 지원하지 않는다.

상점에서는 구매만 지원한다. 상품마다 개당 가격, 1~99개 수량, 합계를 표시하고 구매 후 재화·가방·퀵슬롯 수량을 갱신한다. 상점이 열리면 전투·이동·퀵슬롯 단축키를 멈춘다. Escape, 닫기 버튼, 바깥 영역으로 닫으며 가방이 함께 열려 있으면 게임 입력은 계속 정지한다. 구매 처리 중에는 중복 클릭과 닫기를 막고 구매 요청을 자동 재전송하지 않는다.

| API | 역할 |
|---|---|
| `GET /api/npcs` | 사용 중 NPC의 ID·코드·이름·대화 문구 |
| `GET /api/npcs/{npcId}/image` | 사용 중 NPC의 스토리지 PNG |
| `GET /api/npcs/{npcId}/shop` | 사용 중 NPC의 판매 중 상품 중 사용 중 아이템만 조회 |
| `POST /api/characters/{characterId}/npcs/{npcId}/purchases` | `{ shopItemId, quantity, unitPrice }`로 구매 |

모든 API는 로그인이 필요하고 구매는 CSRF·캐릭터 소유를 검증한다. 서버는 캐릭터 행을 잠근 뒤 NPC·판매 항목·아이템 상태와 해당 NPC의 상품인지 확인한다. NPC와 상품·아이템 정의도 공유 잠금으로 보호한다. `unitPrice`는 조회 시 표시한 단가의 문자열이며 서버의 현재 가격과 다르면 409로 거절한다. 실제 결제 금액은 서버 가격과 수량으로 계산하며 BIGINT 범위 초과와 재화 부족을 거절한다. 가격·합계·구매 후 재화 응답은 정밀도 유지를 위해 문자열을 사용한다.

재화 차감과 아이템 지급은 한 트랜잭션이다. 무기·모자는 개별 보유 UUID와 수량 1로 지급하고 소비·기타는 기존 보유 행에 수량을 합산한다. INTEGER 수량 한도를 넘으면 새 보유 행을 만든다. 전투·소비·캐릭터 삭제·다른 구매와 같은 캐릭터 잠금을 사용해 동시 요청의 초과 차감을 막는다. 기존 `gm_npc`, `gm_npc_shop_item`, `gm_item`, `gm_character`, `gm_character_item`을 사용하므로 추가 마이그레이션은 없다. 판매/매입 API는 제공하지 않는다.

`SHOP_TEST_POSTGRES_URL=jdbc:postgresql://127.0.0.1:포트/shop_test ./gradlew test`로 전용 폐기용 PostgreSQL에서 검증한다. 계정은 `shop_test` / `shop_test_password`다. 가격 변경·재화 부족·상태·소유권·수량 검증, 개별 장비 지급·소비 합산·무료 상품·수량 및 금액 상한·롤백·동시 구매를 확인한다.
