# 캐릭터 레벨과 기본 능력치

Flyway `V11__gm_character_level.sql`에서 레벨 설정 테이블과 캐릭터 성장 상태를 추가한다. 마이그레이션은 게임 백엔드 한 곳에서 실행하며 관리자 서버는 같은 테이블을 읽고 수정한다.

## 저장 구조

`gm_character_level`은 `level` INTEGER PK, `max_hp` INTEGER(1 이상), `attack`·`defense` INTEGER(0 이상), `required_exp` BIGINT(양수 또는 NULL), `reg_dtm`·`mod_dtm`으로 구성한다. `required_exp`는 누적 경험치가 아닌 해당 레벨에서 다음 레벨까지 필요한 양이다. NULL은 현재 최고 레벨이며 부분 고유 인덱스가 NULL 행 중복을 막는다.

`gm_character`에는 `level` INTEGER NOT NULL DEFAULT 1과 `exp` BIGINT NOT NULL DEFAULT 0을 추가한다. 기존 캐릭터도 1레벨·경험치 0이 된다. `level`은 설정 테이블을 FK로 참조하며 참조 동작 옵션은 지정하지 않는다. `exp`는 현재 레벨에서 획득한 경험치로 음수를 허용하지 않는다.

초기 설정은 1레벨 하나이며 최대 체력 100, 공격력 10, 방어력 2, 필요 경험치 NULL이다. 관리자에서 수정할 수 있다. 능력치는 캐릭터마다 복사하지 않는다. 현재 체력은 아직 저장하지 않는다.

## 관리자 레벨 관리

- 활성 ADMIN·SUPER_ADMIN이 `/levels`에서 레벨순 목록(20개 단위)을 보고 각 행에서 최대 체력·공격력·방어력·필요 경험치를 바로 수정한다. 행별 저장은 비동기로 처리해 다른 행에서 수정 중인 값을 유지하며 결과를 해당 행에 표시한다. JavaScript가 없으면 일반 폼 제출로 목록에 돌아온다.
- 목록 아래 추가란에서 새 레벨의 최대 체력·공격력·방어력과 이전 레벨의 필요 경험치를 함께 입력한다. 예: 2레벨 추가 시 `1 → 2레벨 필요 경험치`를 입력한다. 성공하면 새 레벨이 있는 페이지로 이동한다. 저장하지 않은 다른 행이 있으면 먼저 저장하도록 안내한다. 기존 `/levels/new`, `/levels/{level}` 조회 주소는 목록의 해당 위치로 이동한다.
- 추가하는 레벨은 항상 현재 최고 레벨 + 1이다. 이전 최고 레벨의 경험치를 채우고 새 최고 레벨을 NULL 경험치로 등록하는 두 변경을 한 트랜잭션으로 처리한다. 실패하면 이전 경험치도 롤백한다.
- `LOCK TABLE gm_character_level IN SHARE ROW EXCLUSIVE MODE`로 변경을 직렬화한다. 같은 추가 화면에서 동시 등록하면 먼저 저장한 요청만 성공하고 다른 요청은 목록에서 다시 등록하도록 안내한다.
- 최고 레벨 이외에는 필요 경험치가 필수이고 최고 레벨에서는 NULL을 유지한다. 레벨 번호 수정·삭제는 제공하지 않는다. 변경 요청에 로그인과 CSRF 토큰이 필요하다.

## 게임 연결과 범위

캐릭터 목록 API는 레벨 설정을 JOIN해 `level`, `exp`, `maxHp`, `attack`, `defense`, `requiredExp`를 반환한다. 생성 응답도 현재 1레벨 설정을 사용한다. 관리자가 설정을 수정하면 다음 캐릭터 조회부터 변경된 기본 능력치를 응답한다. 클라이언트에서 능력치를 지정하는 입력은 받지 않는다.

전투 피해 판정, 현재 체력, 경험치 지급·차감, 자동 레벨업, 레벨업 시 체력 회복, 장비 능력치 합산은 아직 구현하지 않았다. 필요 경험치를 변경해도 기존 경험치를 소급 조정하거나 자동으로 레벨업하지 않는다.

PostgreSQL 동시성·롤백 테스트는 V11까지 적용한 폐기용 DB에서만 실행한다. `LevelPostgresTests`는 캐릭터·보유 아이템·장착·레벨 설정을 비우므로 공용 개발 DB나 운영 DB에서 실행하면 안 된다.
