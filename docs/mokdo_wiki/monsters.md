# 몬스터 관리

Flyway V14는 몬스터 정의 `gm_monster`와 드롭 정의 `gm_monster_drop`를 만든다. 마이그레이션은 게임 백엔드에서만 실행한다.

## 몬스터 정의

- UUID, 고유 코드, 이름(100자), 설명(관리자 입력 2000자), 레벨, 최대 체력, 공격력, 방어력, 이미지 키, 보상 경험치·재화, 상태, 등록·수정 일시를 저장한다.
- 코드는 소문자·숫자로 시작하는 소문자·숫자·밑줄·하이픈 1~64자이며 등록 후 변경하지 않는다.
- 레벨·최대 체력은 1 이상, 공격력·방어력은 0 이상 INTEGER다. 캐릭터 레벨별 능력치와 독립적으로 설정한다.
- 보상 경험치·재화는 0 이상의 BIGINT이며 재화는 우선 한 종류의 고정 금액이다.
- 상태는 DRAFT(작성 중), ACT(사용 중), INACTIVE(사용 중지)다. 물리 삭제 화면은 제공하지 않는다.

## 드롭 정의

- 몬스터와 아이템 정의를 FK로 연결하며 `(monster_id, item_id)`는 고유하다. FK 참조 동작 옵션은 사용하지 않는다.
- 확률은 NUMERIC(7,4), 0~100 퍼센트이며 소수점 4자리까지 입력한다. 아이템마다 독립적으로 추첨하므로 여러 아이템이 동시에 나오거나 아무것도 나오지 않을 수 있다. 확률 합계는 제한하지 않는다.
- 최소 수량은 1 이상이고 최대 수량은 최소 이상인 INTEGER다.
- 관리자 상세에서 아이템 이름·코드를 검색해 드롭을 추가하고, 기존 행에서 확률·수량을 수정하거나 삭제한다. 중복 아이템 추가를 거절하며 다른 몬스터의 드롭 행을 수정·삭제할 수 없다.
- 몬스터 행을 잠가 드롭 변경을 직렬화한다. 모든 쓰기 요청에는 활성 관리자 로그인과 CSRF 토큰이 필요하다.

## 관리자 화면과 에셋

- 활성 ADMIN과 SUPER_ADMIN은 `/monsters`에서 이름·코드 검색, 상태 필터, 20개 단위 목록을 조회한다.
- `/monsters/new`에서 등록하고 `/monsters/{id}`에서 기본 정보·능력치·보상·이미지·드롭을 관리한다.
- 우선 PNG 한 장을 선택적으로 등록한다. 가로·세로 각각 1~2048 픽셀, 최대 5MB이며 서버에서 시그니처·크기·디코딩을 확인한다. 원본 바이트와 크기를 유지한다.
- 기존 Neon S3 설정을 공유하고 `monsters/{monsterId}/{imageId}.png`에 저장한다. DB 롤백 시 새 업로드를 정리하며 교체 전 파일은 유지한다. 관리자 이미지 조회는 인증이 필요하다.

현재 작업은 정의와 관리자 관리까지다. 게임 내 몬스터 생성·맵 배치·리스폰·전투·실제 드롭 추첨·경험치 및 재화 지급과 애니메이션 구성은 별도 구현 대상이다.
